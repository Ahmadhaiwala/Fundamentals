# 658. Find K Closest Elements

**Difficulty:** Medium  
**Topics:** Array, Two Pointers, Binary Search

## Problem

Given a **sorted** integer array `arr`, two integers `k` and `x`, return the `k` closest integers to `x` in the array.

The result should also be sorted in ascending order.

### Example

```text
Input:
arr = [1,2,3,4,5]
k = 4
x = 3

Output:
[1,2,3,4]
```

---

# 1. First Approach — Start From the Closest Element

My first idea was:

1. Find the element closest to `x`.
2. Start a window from that element.
3. Expand the window to the left or right.
4. At every step, choose whichever side has the closer element.
5. Stop when we have `k` elements.

The initial version looked like this:

```python
class Solution:
    def findClosestElements(self, arr: List[int], k: int, x: int) -> List[int]:

        left = 0
        right = 0

        mina = abs(arr[0] - k)
        indexa = 0

        for index, num in enumerate(arr):
            if abs(arr[index] - x) < mina:
                mina = abs(arr[index] - k)
                indexa = index

        left = indexa
        right = indexa

        s = 1

        while s < k:
            if right < len(arr) and abs(arr[right] - x) < abs(arr[left] - x):
                right += 1

            elif left > 0 and abs(arr[right] - x) >= abs(arr[left] - x):
                left -= 1

            elif right < len(arr):
                right += 1

            elif left > 0:
                left -= 1

            else:
                break

            s += 1

        return arr[left:right + 1]
```

---

# 2. Bugs in the First Approach

## Bug 1 — Using `k` instead of `x`

The closest element needs to be found relative to `x`.

Wrong:

```python
mina = abs(arr[0] - k)
```

Correct:

```python
mina = abs(arr[0] - x)
```

Similarly:

```python
mina = abs(arr[index] - x)
```

---

## Bug 2 — `indexa = indexa`

This does nothing:

```python
indexa = indexa
```

We need to store the new closest index:

```python
indexa = index
```

---

## Bug 3 — Missing `abs()`

Distance from `x` should always be positive:

```python
abs(arr[i] - x)
```

Not:

```python
arr[i] - x
```

For example:

```text
arr[i] = 2
x = 3

2 - 3 = -1
```

But the actual distance is:

```text
|2 - 3| = 1
```

---

## Bug 4 — Comparing the wrong elements

When expanding a window, we should compare the elements that are **outside** the current window:

```text
             current window
                  ↓
[ ...  left-1 | left ... right | right+1  ... ]
        ↑                              ↑
     candidate                       candidate
```

Therefore compare:

```python
abs(arr[left - 1] - x)
```

with:

```python
abs(arr[right + 1] - x)
```

---

# 3. Corrected Two-Pointer Expansion Approach

After fixing the idea, the approach becomes:

```python
class Solution:
    def findClosestElements(self, arr: List[int], k: int, x: int) -> List[int]:

        # Find the element closest to x
        mina = abs(arr[0] - x)
        indexa = 0

        for index, num in enumerate(arr):
            if abs(num - x) < mina:
                mina = abs(num - x)
                indexa = index

        left = indexa
        right = indexa

        # We already have one element
        s = 1

        while s < k:

            # No element available on the left
            if left == 0:
                right += 1

            # No element available on the right
            elif right == len(arr) - 1:
                left -= 1

            # Compare the two possible candidates
            elif abs(arr[left - 1] - x) <= abs(arr[right + 1] - x):
                left -= 1

            else:
                right += 1

            s += 1

        return arr[left:right + 1]
```


Final window:

# 7. Optimal Approach — Binary Search on the Window

The important observation is:

> We don't actually need to find the single closest element.

We need to find the **best window of exactly `k` elements**.

Because the array is sorted, every valid answer is a contiguous window.

For example:

```text
arr = [1,2,3,4,5]
k = 3
```

Possible windows are:

```text
[1,2,3]
[2,3,4]
[3,4,5]
```

We can binary-search for the best starting position.

---

# 8. Search Space

A window contains exactly `k` elements.

Therefore, if:

```text
n = len(arr)
```

the possible starting indices are:

```text
0 ... n-k
```

So initialize:

```python
left = 0
right = len(arr) - k
```

Example:

```text
arr length = 7
k = 4

possible starts:

0
1
2
3
```

Because:

```text
7 - 4 = 3
```

---

# 9. The Key Comparison

Suppose:

```text
mid
```

is the current starting position.

The current window is:

```text
arr[mid : mid + k]
```

We compare:

```python
arr[mid]
```

with:

```python
arr[mid + k]
```

Visually:

```text
                 current window
                       ↓
[ ... | arr[mid] | ................. | arr[mid+k] | ... ]
         ↑                                  ↑
       remove                             add
```

If:

```python
x - arr[mid] > arr[mid + k] - x
```

then the element on the right is closer to `x`.

Therefore, move the window right:

```python
left = mid + 1
```

Otherwise, the current window is better or equally good:

```python
right = mid
```

---

# 10. Optimal Code

```python
class Solution:
    def findClosestElements(self, arr: List[int], k: int, x: int) -> List[int]:

        left = 0
        right = len(arr) - k

        while left < right:

            mid = (left + right) // 2

            if x - arr[mid] > arr[mid + k] - x:
                left = mid + 1
            else:
                right = mid

        return arr[left:left + k]
```

# 13. Why Does the Comparison Work?

This is the main trick to understand.

Suppose we are considering:

```text
arr[mid : mid+k]
```

We have two choices:

### Keep the current window

```text
arr[mid], ..., arr[mid+k-1]
```

### Move the window right

```text
arr[mid+1], ..., arr[mid+k]
```

The only important elements that change are:

```text
arr[mid]
```

and:

```text
arr[mid+k]
```

Everything between them remains in both windows.

So we only need to compare:

```text
distance of arr[mid] from x
```

against:

```text
distance of arr[mid+k] from x
```

Because the array is sorted, this tells us which direction the optimal window lies in.

---

# 14. Why Not Just Find the Closest Element?

Finding the closest element is tempting:

```text
Find x's closest element
        ↓
Expand left/right
        ↓
Choose closest candidate
```

But it introduces extra boundary logic and isn't necessary.

The better mental model is:

```text
Sorted array
     ↓
Possible windows of size k
     ↓
Binary search those windows
     ↓
Return the best window
```

This is a classic example of:

> **Binary search on the answer space.**

We aren't searching for `x`.

We are searching for the **starting index of the answer**.

---

# 15. Complexity Comparison

| Approach | Time | Space |
|---|---:|---:|
| Find closest + expand | `O(n + k)` | `O(1)` |
| Binary search window | `O(log(n-k) + k)` | `O(1)` |

The final slicing:

```python
arr[left:left+k]
```

takes `O(k)` because we have to return `k` elements.

Therefore the optimal approach is:

```text
Time:  O(log(n-k) + k)
Space: O(1)
```

# 16. Pattern to Remember

When you see:

- Sorted array
- Need exactly `k` elements
- Answer must remain contiguous
- Need elements closest to some `x`

Think:

```text
Binary Search on Window
```

Template:

```python
left = 0
right = len(arr) - k

while left < right:

    mid = (left + right) // 2

    if x - arr[mid] > arr[mid + k] - x:
        left = mid + 1
    else:
        right = mid

return arr[left:left + k]
```

## Core idea

```text
arr[mid]       → element we may remove
arr[mid + k]   → element we may add
```

If the right candidate is closer:

```python
left = mid + 1
```

Otherwise:

```python
right = mid
```

# Final Takeaway

My original approach was:

```text
Find closest element
        ↓
Expand window
        ↓
Compare left/right candidates
```

It works with careful boundary handling and has:

```text
O(n + k)
```

The optimized approach recognizes that the array is sorted and that the answer is a window:

```text
Find best window
        ↓
Binary search its starting index
        ↓
Return k elements
```

with:

```text
O(log(n-k) + k)
```

The **most important thing to remember for interviews** is not just the code. Remember the transformation:

```text
"Find k closest elements"
          ↓
"Find the best contiguous window of size k"
          ↓
"Binary search the window's starting position"
```
